# 商品与统一订单管理真实接口重构设计

## 背景与目标

当前商品列表和订单列表仍主要依赖本地模拟数据。商品页只接入了后台新增商品接口，订单页同时混有陪玩服务字段、本地编辑删除和当前管理员购物车下单入口，与后台管理 OpenAPI 不一致。

本次重构将商品管理和订单管理切换为 Mystikos Server API 的真实后台接口。陪玩作为商品的一种，由统一订单中的商品明细承载；前端不再维护商城订单与陪玩订单两套后台模型。

## 范围

### 商品管理接口

- `GET /api/v1/manage/products`：分页查询商品
- `GET /api/v1/manage/products/{productId}`：查询商品详情
- `POST /api/v1/manage/products`：新增商品（已完成初步接入，本次纳入完整页面流程）
- `PUT /api/v1/manage/products/{productId}`：编辑商品及调整上下架状态

### 统一订单管理接口

- `GET /api/v1/manage/orders`：分页查询订单
- `GET /api/v1/manage/orders/{orderId}`：查询订单详情
- `PUT /api/v1/manage/orders/{orderId}/start-fulfilling`：开始处理订单
- `PUT /api/v1/manage/orders/{orderId}/ship`：订单发货
- `PUT /api/v1/manage/orders/{orderId}/complete`：完成订单
- `PUT /api/v1/manage/orders/{orderId}/cancel`：取消订单
- `PUT /api/v1/manage/orders/{orderId}/refund`：订单退款

### 不在本次范围

- 管理员创建订单。后台 OpenAPI 没有该接口，移除现有前端入口。
- 删除订单或任意编辑订单字段。后台 OpenAPI 没有对应能力。
- 商品库存编辑。`UpdateProductRequest` 没有库存字段；初始库存只在新增时提交。
- 商品图片上传。新增和编辑表单继续接收已上传的 URL 或 objectKey，文件上传另行接入。
- 后端不支持的关键词搜索、时间筛选或商品类型筛选。

## 数据模型

### 商品

`ProductView` 包含：

- `id`
- `categoryId`
- `name`
- `description`
- `price`
- `images`
- `status`：`ON_SHELF | OFF_SHELF`

商品分页响应统一映射为 `PageResult<ProductView>`，包含 `records、total、pageNum、pageSize、pages`。列表不再展示后端未返回的库存、陪玩师等模拟字段。

新增请求包含可选 `categoryId、description、images`，必填 `name、price、initialStock`。编辑请求包含可选 `categoryId、description、images、status`，必填 `name、price`。

### 统一订单

`OrderResponse` 包含：

- `orderId`
- `patronId`
- `items`
- `totalAmount`
- `shippingAddress`
- `status`
- `createdAt`

每个 `OrderLineItemResponse` 包含 `productId、productNameSnapshot、unitPriceSnapshot、quantity、subtotal`。陪玩与普通商品统一通过这些订单行展示，前端不根据业务类型拆分订单结构。

## API 层设计

新增独立的后台商品和后台订单 API 模块，避免将管理接口继续混入面向用户下单的 `commerce.ts`：

- `src/api/manage-products.ts`
- `src/api/manage-orders.ts`

API 层负责请求路径、参数和统一响应解包，不保存页面状态。列表查询只发送有值的可选筛选条件，避免将空字符串传给后端。

页面层负责加载、筛选、分页、抽屉开关和操作反馈。新增、编辑或状态流转成功后重新获取当前页，服务端返回结果是唯一真实数据源。

## 商品管理页面

商品页改为专用页面，不再使用面向模拟 CRUD 的通用 `ModulePage`。

### 顶部信息

- 商品总数：使用分页响应 `total`
- 当前页上架数：按当前页 `ON_SHELF` 记录计算
- 当前页下架数：按当前页 `OFF_SHELF` 记录计算

当前页统计必须明确标注，避免将一页数据误认为全量统计。

### 筛选与列表

- 状态筛选：全部、已上架、已下架
- 分页：服务端 `pageNum、pageSize`
- 操作：刷新、新增商品
- 列表列：商品 ID、主图与名称、分类 ID、价格、状态、操作

图片值可直接显示时作为主图；没有图片或无法加载时显示统一占位，不渲染持续报错的破图。

### 详情与编辑

点击商品行或详情按钮后打开右侧抽屉，并通过详情接口加载最新数据。抽屉展示图片、名称、描述、分类 ID、价格和状态。

新增与编辑使用不可点击遮罩关闭的表单弹窗：

- 新增字段：名称、分类 ID、价格、初始库存、描述、图片 URL/objectKey 列表
- 编辑字段：名称、分类 ID、价格、描述、图片 URL/objectKey 列表、上下架状态

价格必须大于零，初始库存必须为非负整数，可选分类 ID 必须为正整数。提交期间禁用关闭与重复提交；成功后关闭弹窗并刷新当前页，失败时保留表单。

## 统一订单管理页面

订单页移除本地模拟 CRUD、管理员购物车下单、陪玩师、支付方式、编辑和删除等无真实接口支持的内容。

### 顶部信息

- 当前查询结果总量：使用分页响应 `total`
- 当前页待处理量：当前页 `PAID` 数量
- 当前页处理中量：当前页 `FULFILLING` 数量

### 筛选与列表

- 状态筛选：全部及八种后端状态
- 买家用户 ID：正整数精确筛选
- 分页：服务端 `pageNum、pageSize`
- 操作：查询、重置、刷新
- 列表列：订单 ID、买家 ID、商品摘要、商品件数、总金额、状态、创建时间、操作

商品摘要展示第一条订单行的商品名称；多项订单显示“等 N 项”。状态以中文标签和统一颜色展示，同时保留枚举值作为程序判断依据。

### 订单详情

点击订单行或详情按钮后打开右侧抽屉，并调用后台详情接口。抽屉展示：

- 订单 ID、买家 ID、状态和创建时间
- 收货地址
- 商品明细表：商品 ID、名称快照、单价、数量、小计
- 总金额
- 当前状态允许的操作

窄屏下抽屉使用接近全屏宽度；商品明细表允许横向滚动。

## 订单状态流转

前端按钮严格按接口文档约束显示：

| 当前状态 | 可执行操作 |
| --- | --- |
| `DRAFT` | 取消 |
| `PENDING_PAYMENT` | 取消 |
| `PAID` | 开始处理、取消、退款 |
| `FULFILLING` | 发货、退款 |
| `SHIPPED` | 完成、退款 |
| `COMPLETED` | 退款 |
| `CANCELLED` | 无 |
| `REFUNDED` | 无 |

开始处理、发货和完成使用普通确认弹窗。取消和退款使用危险操作确认样式，并提示会释放预占库存。操作提交期间锁定同一订单的按钮，避免重复请求。

操作成功后使用接口返回的最新订单更新详情，并重新获取列表；操作失败时保留抽屉、筛选和分页状态，直接展示后端错误。

## 加载、错误与空状态

- 首次加载和筛选加载使用表格加载态，不先展示模拟数据。
- 列表为空时显示与当前筛选条件相关的空状态。
- 详情独立加载，避免阻塞整个列表。
- 后端业务错误通过统一响应解包转换为用户可读消息。
- 切换筛选条件时回到第一页；刷新保留当前筛选和页码。
- 查询返回页数缩减导致当前页越界时，回到最后一个有效页重新请求。

## 测试与验证

### API 合约测试

- 商品列表、详情、编辑和新增的请求路径、方法、参数及响应解包
- 订单列表、详情和五种状态操作的请求路径、方法、参数及响应解包
- 空筛选条件不进入查询参数

### 页面行为测试

- 商品列表按服务端分页渲染，筛选后回到第一页
- 新增和编辑成功刷新列表，失败保留表单
- 商品详情按 ID 获取真实数据
- 订单状态与操作按钮映射正确
- 订单详情渲染商品快照、地址和金额
- 状态操作成功更新并刷新，失败保留当前上下文
- 加载、空数据和错误状态可见

### 完整验证

- `npm run test`
- `npm run lint`
- `npm run build`
- 启动开发服务器，在浏览器中检查商品、订单页面及控制台
- 同步更新 `README.md` 的真实接口、页面能力和变更记录

## 实施顺序

1. 定义真实商品和订单类型及状态映射。
2. 以失败测试约束后台商品与订单 API 模块。
3. 重构商品管理页并验证分页、详情、新增和编辑。
4. 重构统一订单管理页并验证筛选、详情和状态流转。
5. 清理页面不再使用的模拟数据依赖和虚假操作。
6. 更新 README，执行完整自动化及浏览器验证。
